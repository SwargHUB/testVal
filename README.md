# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT` (например, `PORT=3111 node server.mjs`).

Тесты:

```sh
npm test          # или: node --test
```

Тесты поднимают сервер на случайном свободном порту, ничего не требуют от внешних сервисов и проверяют API во всех сценариях сбоя.

### `server.mjs` — было → стало

**Было:**

- `JSON.parse` тела запроса без `try/catch`: битый JSON ронял обработчик, а верхний `catch` отдавал 500 `server_error` вместо 400;
- поле `text` не проверялось: пустая строка, пробелы, отсутствующее поле и нестроковый тип уходили в модель;
- ответ модели не проверялся: `[bad-json]` ронял сервер, а `[bad-topic]` (`refund`) и `[empty-draft]` (пустая строка) проходили как «успех» с невалидными данными;
- таймаута не было: `[timeout]` держал запрос 1200 мс, а реальная модель — неограниченно долго;
- порт занимался сразу при импорте — модуль нельзя было поднять в тестах;
- ошибки отдавались вразнобой, HTML-страница отдавалась без маршрутизации методов.

**Стало:**

- `readJsonBody()` (лимит тела 64 КБ) + `extractText()` → `400 {"status":"invalid_input"}` на пустом, пробельном, отсутствующем, нестроковом `text` и на битом JSON;
- `requestModel()` — `AbortController` + `Promise.race` с таймером 300 мс: и запрос к модели отменяется, и ответ ждёт не дольше лимита;
- `normalizeModelOutput()` — тема только из `delivery | pricing | other`, черновик только непустая строка; любое несоответствие → `manual_review`, а не «успешный» пустой ответ;
- единый маршрутизатор: `GET /` → HTML, `POST /api/triage` → API, остальное → `404 {"status":"not_found"}`; неожиданные ошибки → `500 {"status":"server_error"}`;
- `export createTriageServer()` / `export startServer()` — сервер поднимается только при `node server.mjs`, поэтому его можно импортировать в тестах на случайном порту.

### `index.html` — было → стало

**Было:** сырой `JSON.stringify(await reply.json())` без разбора; пустая заявка отправлялась на сервер; ответы 400/500 показывались как результат; ни таймаута, ни обработки сетевых ошибок; при сбое на экране оставался предыдущий черновик.

**Стало:**

- пустой ввод не отправляется: страница сообщает «Введите текст заявки» и возвращает фокус в поле;
- успех: тема заявки по-русски, черновик ответа и кнопка «Скопировать черновик»;
- `manual_review`: понятное сообщение «Требуется ручной разбор: …», **предыдущий черновик очищается**, а исходная заявка остаётся на экране для ручной обработки;
- таймаут клиента 5 с (`AbortController`) и сетевые ошибки тоже приводят к ручному разбору, а не к молчаливому пустому результату;
- кнопка блокируется на время запроса, ответы без JSON не ломают страницу.

### Контракт API `POST /api/triage`

Принимает JSON `{"text": "…"}` и всегда отвечает предсказуемым JSON.

| Ситуация | HTTP | Тело |
| --- | --- | --- |
| Корректный ответ модели | 200 | `{"status":"ready","topic":"delivery\|pricing\|other","draft":"…"}` |
| Таймаут модели (лимит 300 мс) | 200 | `{"status":"manual_review","topic":null,"draft":null}` |
| Ошибка модели, невалидный JSON, неизвестная тема, пустой черновик | 200 | `{"status":"manual_review","topic":null,"draft":null}` |
| Пустой, пробельный, отсутствующий или нестроковый `text`, битый JSON, тело больше 64 КБ | 400 | `{"status":"invalid_input"}` |
| Неизвестный маршрут | 404 | `{"status":"not_found"}` |

Ключевые решения:

- Валидация входа до обращения к модели (`server.mjs:29`, `server.mjs:67`): пустая строка, пробелы, отсутствующее поле, нестроковый тип и сломанный JSON дают `400 invalid_input`.
- Ограничение ожидания модели 300 мс (`server.mjs:50`): запрос идёт с `AbortSignal`, и результат модели дополнительно ограничен по времени через `Promise.race`, поэтому «зависшая» модель не блокирует менеджера.
- Проверка ответа модели (`server.mjs:36`): тема должна быть одной из `delivery`, `pricing`, `other`, черновик — непустой строкой. Любое несоответствие — это `manual_review`, а не «успешный» пустой ответ.
- Имитатор `mock-ai.mjs` не изменён: его метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` используются как отдельные сценарии сбоя.

## Тесты

`test/api.test.mjs` — 15 исполняемых сценариев:

- успех: `delivery`, `pricing`, `other`, непустой черновик;
- пустой ввод: пустая строка, пробелы, отсутствующее поле, нестроковый тип, битый JSON → `400 invalid_input`;
- сбои: `[timeout]` (плюс проверка, что ответ пришёл быстрее лимита в 1000 мс вместо 1200 мс ожидания модели), `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` → `manual_review` с `topic: null` и `draft: null`;
- сервисные проверки: `404` на неизвестный маршрут и отдача HTML на `/`.

Запуск: `npm test` (или `node --test`). Дополнительно сценарии сбоя можно проверить вручную, вставив в текст заявки соответствующую метку.

## Польза для менеджера

Менеджер получает классификацию заявки и готовый черновик ответа за секунды, поэтому сокращается время ответа клиенту, а при сбое модели он сразу видит, что заявку нужно разобрать вручную, и никогда не отправит клиенту пустой или некорректный ответ.

Как измерить: среднее время ответа (AHT) по заявкам, доля заявок, закрытых с готовым черновиком, доля ответов, отправленных без правок менеджером, и доля `manual_review` — в норме она близка к нулю и показывает качество подключённой модели.

## Исходное задание

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.
